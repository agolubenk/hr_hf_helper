# Документация страницы: Заявки на подбор (hiring-requests/page.tsx)

## Общее описание

Страница управления заявками на подбор персонала. Позволяет создавать, просматривать, фильтровать и группировать заявки в двух режимах отображения: таблица и блоки.

## Компоненты страницы

### 1. RequestsSearchFilters
- **Расположение**: `@/components/requests/RequestsSearchFilters`
- **Назначение**: Поиск и фильтры для заявок
- **Пропсы**:
  - `searchQuery`: текущий поисковый запрос
  - `onSearchChange`: обработчик изменения поиска
  - `selectedRecruiter`: выбранный рекрутер ('all' или имя)
  - `onRecruiterChange`: обработчик изменения рекрутера
  - `selectedStatus`: выбранный статус ('all' | 'planned' | 'in_process' | 'cancelled' | 'closed')
  - `onStatusChange`: обработчик изменения статуса
  - `selectedPriority`: выбранный приоритет ('all' | 'high' | 'medium' | 'low')
  - `onPriorityChange`: обработчик изменения приоритета
- **Логика**: 
  - Поле поиска по названию, ID или отделу
  - Фильтр по рекрутеру
  - Фильтр по статусу
  - Фильтр по приоритету
  - Кнопка "Поиск" (TODO: реализовать функциональность)
- **Связи**: Передает изменения фильтров в родительский компонент

### 2. RequestsStats
- **Расположение**: `@/components/requests/RequestsStats`
- **Назначение**: Статистика по заявкам
- **Пропсы**:
  - `total`: общее количество заявок
  - `planned`: количество запланированных заявок
  - `inProcess`: количество заявок в процессе
  - `cancelled`: количество отмененных заявок
  - `closed`: количество закрытых заявок
- **Логика**: Отображает 5 карточек со статистикой с цветовыми индикациями
- **Связи**: Получает данные из вычисленных значений на основе `mockRequests`

### 3. RequestsTable
- **Расположение**: `@/components/requests/RequestsTable`
- **Назначение**: Таблица всех заявок (режим "Все")
- **Пропсы**:
  - `requests`: массив заявок для отображения
  - `onView`: обработчик просмотра заявки
  - `onEdit`: обработчик редактирования заявки
- **Логика**: 
  - Отображает все заявки в табличном виде
  - Колонки: Грейд, Проект, Рекрутер, Статус, Сроки, Факт/SLA, T2H | SLA, Кандидат, Действия
- **Связи**: Используется только в режиме `displayMode === 'all'`

### 4. RequestListItem
- **Расположение**: `@/components/requests/RequestListItem`
- **Назначение**: Элемент списка заявки (режим "Блоками")
- **Пропсы**:
  - `request`: основная заявка для отображения
  - `onClick`: обработчик клика (переход на детальную страницу)
  - `requestsCount`: количество заявок в группе (опционально)
  - `requests`: массив всех заявок в группе (опционально)
- **Логика**: 
  - Отображает основную информацию о заявке
  - Если передано несколько заявок - показывает развернутую таблицу
  - Кнопка разворота для детальной таблицы (если есть данные)
- **Связи**: Используется только в режиме `displayMode === 'blocks'`

### 5. CreateRequestModal
- **Расположение**: `@/components/requests/CreateRequestModal`
- **Назначение**: Модальное окно создания новой заявки
- **Пропсы**:
  - `isOpen`: флаг открытости
  - `onClose`: обработчик закрытия
  - `onSave`: обработчик сохранения (получает данные заявки)
- **Логика**: 
  - Форма создания заявки с полями
  - Валидация обязательных полей
  - Сохранение через API

## Состояние компонента

### State переменные:
- `displayMode`: режим отображения ('all' | 'blocks')
- `searchQuery`: поисковый запрос
- `selectedRecruiter`: выбранный рекрутер ('all' или имя)
- `selectedStatus`: выбранный статус ('all' | 'planned' | 'in_process' | 'cancelled' | 'closed')
- `selectedPriority`: выбранный приоритет ('all' | 'high' | 'medium' | 'low')
- `isCreateModalOpen`: флаг открытия модального окна создания

## Функции и обработчики

### Вычисление статистики
- `totalRequests`: `mockRequests.length`
- `plannedRequests`: количество заявок со статусом 'planned'
- `inProcessRequests`: количество заявок со статусом 'in_process'
- `cancelledRequests`: количество заявок со статусом 'cancelled'
- `closedRequests`: количество заявок со статусом 'closed'

### filteredRequests
Отфильтрованный список заявок по четырем условиям:
1. Поиск: название, ID или отдел содержит `searchQuery` (без учета регистра)
2. Рекрутер: совпадает с `selectedRecruiter` (или 'all')
3. Статус: совпадает с `selectedStatus` (или 'all')
4. Приоритет: совпадает с `selectedPriority` (или 'all')

### groupedRequests
- **Назначение**: Группировка заявок по названию вакансии
- **Логика**: 
  - Используется только в режиме `displayMode === 'blocks'`
  - Создает объект, где ключ - название вакансии, значение - массив заявок
  - Позволяет видеть все заявки на одну и ту же вакансию вместе
- **Структура**: `Record<string, Request[]>` (ключ - название вакансии)

## Фильтрация и поиск

### Поиск (searchQuery)
- **Поле**: TextField в `RequestsSearchFilters`
- **Логика**: 
  - Ищет по названию заявки (без учета регистра)
  - Ищет по ID заявки (точное совпадение в строке)
  - Ищет по отделу (без учета регистра)
- **Поведение**: Фильтрация происходит в реальном времени

### Фильтр по рекрутеру (selectedRecruiter)
- **Поле**: Select в `RequestsSearchFilters`
- **Опции**: "Все рекрутеры", список рекрутеров
- **Логика**: Фильтрует по точному совпадению имени рекрутера
- **TODO**: Загружать список рекрутеров из API

### Фильтр по статусу (selectedStatus)
- **Поле**: Select в `RequestsSearchFilters`
- **Опции**: "Все статусы", "Планируется", "В процессе", "Отменена", "Закрыта"
- **Логика**: Фильтрует по статусу заявки

### Фильтр по приоритету (selectedPriority)
- **Поле**: Select в `RequestsSearchFilters`
- **Опции**: "Все приоритеты", "Высокий", "Средний", "Низкий"
- **Логика**: Фильтрует по приоритету заявки

## Режимы отображения

### Режим "Все" (displayMode === 'all')
- **Компонент**: `RequestsTable`
- **Особенности**: 
  - Отображает все заявки в табличном виде
  - Полная информация в колонках
  - Подходит для детального анализа

### Режим "Блоками" (displayMode === 'blocks')
- **Компонент**: `RequestListItem`
- **Особенности**: 
  - Группирует заявки по названию вакансии
  - Показывает основную информацию о группе
  - Разворачиваемая таблица с деталями всех заявок в группе
  - Подходит для работы с несколькими заявками на одну вакансию

### Переключатель режимов
- **Компонент**: `SegmentedControl` с опциями "Все" и "Блоками"
- **Логика**: При изменении перерисовывает список заявок

## Моковые данные

### mockRequests
Массив объектов заявок с полями:
- `id`: уникальный идентификатор
- `title`: название вакансии
- `grade`: грейд (Junior+, Middle, Middle+, Senior, и т.д.)
- `project`: проект (может быть null)
- `recruiter`: рекрутер, ведущий заявку
- `recruiterDays`: количество дней работы рекрутера
- `status`: 'planned' | 'in_process' | 'closed' | 'cancelled'
- `statusDate`: дата изменения статуса
- `startDate`, `endDate`: даты начала и окончания подбора
- `isOverdue`: флаг просрочки
- `factDays`: фактическое количество дней подбора
- `slaDays`: SLA по количеству дней
- `slaStatus`: 'normal' | 'risk' | 'overdue' | 'on_time'
- `t2hDays`: время до найма в днях (опционально)
- `t2hSlaDays`: SLA по времени до найма
- `candidate`: информация о найденном кандидате (опционально)
- `department`: отдел/департамент
- `priority`: 'high' | 'medium' | 'low'
- `technologies`: массив технологий
- `candidates`: количество кандидатов
- `date`: дата создания заявки
- `hasWarning`: флаг наличия предупреждения
